# Управление участниками

Администратор открывает «Профиль → Управление участниками», ищет по ID, username или имени и выбирает участника.

- «Начислить / Списать»: положительная сумма с одним десятичным знаком, обязательная причина. Списание не уводит баланс ниже нуля. Изменение баланса и аудит выполняются атомарно.
- «Заблокировать / Разблокировать»: обязательная причина. Блокировка закрывает игровые действия и скрывает публичный профиль/аватар, не отменяет существующие прогнозы и не удаляет историю. Получение результатов и расчёт ранее сделанных прогнозов продолжаются.
- Заблокированный участник видит собственный профиль, баланс и историю, может создать обращение и отозвать согласие. Вернуть публичность в обход блокировки нельзя. После разблокировки публичность автоматически не включается.
- «Профиль и история»: собственная карточка участника для администратора с подробными операциями.
- «Скрыть публичный профиль»: скрывает профиль и аватар без блокировки аккаунта.

Ник остаётся неизменяемым. Администраторов нельзя блокировать через этот интерфейс/API. Роли определяются по ADMIN_IDS на сервере. Физического удаления аккаунтов, ответов, операций и прогнозов здесь нет.

API: GET `/api/admin/users?q=...`, POST `/api/admin/adjust` с user_id/amount/reason, POST `/api/admin/users/action` с user_id/action/reason (block, unblock, hide_profile). Все изменения журналируются. Модерация меняет состояние пользователя и сохраняет аудит в одной транзакции. Ограничения игровой записи дополнительно проверяются триггерами БД.

Миграция `0017_user_moderation.sql` добавляет поля и ограничения, не изменяет исторические суммы или ответы. Для публикации применять штатный workflow с резервной точкой, репетицией миграций и проверкой сохранности истории.
